. JVM Metrics

JVM metrics tell you what is happening inside a Java application.

Important JVM metrics
Metric	What to monitor	Problem indication
Heap Memory	Used vs Max heap	Memory leak / insufficient heap
Non-Heap Memory	Metaspace usage	Classloader leak
GC Count	Number of GC events	Excessive GC
GC Pause Time	Time application stops	High latency
Thread Count	Live threads	Thread leak
CPU Usage	Process CPU	CPU bottleneck
Class Count	Loaded classes	Metaspace issues
Example Prometheus metrics

jvm_memory_max_bytes
jvm_gc_pause_seconds
jvm_threads_live_threads
jvm_threads_peak_threads
process_cpu_usage
2. Garbage Collection (GC)

Java automatically removes objects that are no longer needed.

6
JVM Heap Areas
JVM Heap

├── Young Generation
│   ├── Eden
│   ├── Survivor S0

Types of GC
Minor GC
Cleans Young Generation
Usually fast
Happens frequently
Major GC
Cleans Old Generation
More expensive
Full GC
Cleans the entire heap
Can cause Stop-The-World pauses
High Full GC frequency is a production concern
Production symptom
Application latency increases
        ↓
GC pauses increase
        ↓
CPU may increase
        ↓
Requests timeout
What would you monitor?
GC frequency
GC pause duration
Heap usage
Old generation utilization
Full GC count

Interview answer:

If application latency increases, I check GC pause time and Full GC frequency. Frequent long GC pauses can cause Stop-The-World events, making the application unresponsive even when CPU utilization is low.

4. Blocked Threads

A thread can be in different states.

RUNNABLE
BLOCKED
WAITING
TIMED_WAITING
TERMINATED
BLOCKED

A thread is waiting to acquire a lock.

Example:

synchronized(lock) {
    // another thread may hold this lock
}

If Thread A holds the lock:

Thread A → Holding Lock
Thread B → BLOCKED
Thread C → BLOCKED
Thread D → BLOCKED

This can create application slowness.

How to investigate?

Take a thread dump:

jstack <PID>

Or:

jcmd <PID> Thread.print

Look for:

BLOCKED
WAITING
TIMED_WAITING
Interview scenario

Application CPU is only 30%, but latency is high. What could be happening?

Answer:

CPU may not be the bottleneck. I would check thread pool saturation and thread dumps. Threads could be blocked waiting for database connections, locks, external API responses, or synchronized resources.
